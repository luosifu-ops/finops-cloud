### 1. 知识库管理菜单归属

- 移动前：侧栏「运营部」分组内
- 移动后：侧栏「入职与成长」分组内，位置在「专业基础知识」（公司简介 / 制度 / 知识分类 / 视频学习 / 在线考试）之后
- 路径 `ops/knowledge-manage` 与路由 name 未变，页面本身零改动

### 2. 线索分配弹窗（根因 + 修复）

**根因**（生产实测）：`GET /api/growth/roles/` 返回 `{"count":0,"results":[]}`，`GET /api/growth/roles/me/` 返回 `{"has_role":false,"can_view_all":true}` —— 生产增长中心**没有配置任何 GrowthRole**，而弹窗原来只从 GrowthRole 取「归属运营 / 承接人」名单，导致两个下拉全空、无法选到任何个人。另有 `loadRole()` → `loadGrowthRoles()` 的异步竞态：权限判定未完成时人员不会加载。

**修复**：
1. 人员主数据源改为真实员工名单 `/api/accounts/users/`（后端已过滤 `is_active=True`）
2. GrowthRole 若已配置，仍优先采用其 OPS / CLOSER 归类（配置即生效，不丢原有能力）
3. 部门匹配放宽为关键字（运营 / 电销、销售、成交），避免部门命名差异导致空列
4. **兜底**：某一列仍为空时退化为「全公司在职员工」，保证任何情况下都能选到人
5. 竞态消除：`watch(canManage)` 在权限就绪后自动加载名单（immediate）
6. 两个下拉改为 `filterable` 可搜索、带 `loading`；选项右侧展示所属部门
7. `submitAssign` 增加「未选线索」判空；确认分配按钮始终可点击（未选人时给出明确提示）

后端分配逻辑（`LeadExtViewSet.assign`）原本完好，未改动：写 `ops_owner` / `closer`、`in_pool=False`、关闭 `LeadPool(WAITING→CLAIMED)`、写 `LeadFlow(action=ASSIGN)`。

### 3. 合同订单 → 外勤流转

- **接口**：`POST /api/growth/field-tasks/` 新增支持 `assignee`（外勤人员）。带 `assignee` 时自动回写 `assigned_by`（下发人）并写一条 `FieldProgress(node="订单下发")` 留痕；不带 `assignee` 时行为与原来完全一致（进入公共待接收池）
- **弹窗** `FieldTransferDialog.vue`：新增「下发外勤人员」（可搜索、可留空）与「备注」；任务类型随业务类型自动带出；提交后提示派单号
- **入口**：`contracts/sales`（电销部合同）、`contracts/ops`（运营部合同）新增「转外勤」；来源单号取 `HT-0001` 形式回写外勤任务，便于双向追溯。原 `sales/contracts`、`growth/contracts`、客户档案的「转外勤」入口保持可用，共用同一弹窗
- 状态保持「待接收」（PENDING），外勤仍需接单，不跳过接单环节
