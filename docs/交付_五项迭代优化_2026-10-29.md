## 四、部署说明

### 1. 本轮实际执行步骤（已在生产完成）

```bash

rsync -az --exclude 'venv/' --exclude 'db.sqlite3' --exclude '__pycache__/' \
      --exclude '*.pyc' --exclude 'media/' --exclude 'staticfiles/' \
      backend/ ubuntu@140.143.85.54:/tmp/finops-backend-new/

# 3) 覆盖到生产（不带 --delete，旧产物保留，避免老缓存页面 404）

  --exclude "media/" --exclude "staticfiles/" --exclude ".env" \
```

## 五、注意事项与遗留

1. **公海统计接口是新增只读端点**，不改变任何既有写入逻辑；若后续要按平台维度统计，在同一 action 内加 filter 即可。
2. **外勤「再分配」对普通外勤开放了写权限**，但有「仅本单负责人」的强校验，且全程写 `FieldProgress`，可追溯、可审计。
3. **本轮未改动**：薪酬页等带 `@change` 联动的人员下拉（按约束保持原样）；公海后端「领取/分配」核心逻辑（原本已实现）。
4. **历史遗留提示（非本轮引入）**：`migrate` 会提示 `accounting/common/sales` 存在未生成迁移的模型差异，经核查**仅为 `id` 字段 `AutoField→BigAutoField` 的类型声明差异，无新增字段、不影响运行**。为遵守「不覆盖」原则本轮未强行生成迁移；若要彻底消除该提示，需单独评审后再 `makemigrations`。
5. **构建注意**：`vite.config.js` 的 `emptyOutDir: false` 是沙箱限制下的妥协产物，长期会让 `backend/spa/assets` 累积历史 chunk（当前 2722 个）。建议后续在本地环境改为 `true` 做一次清理，或按本文档的「独立目录构建 → 切换」方式发布。
6. **本地测试数据已清理**：临时新增人员「测试新人乙」及测试派单流水（4 条 `FieldProgress`）已删除；`field01` 账号保留（测试用外勤号）。
