## 一、权限评估结论

### 1.1 总判定

| 项 | 结论 |
|---|---|
| 系统是否已有这套权限规则 | **主干已有**（`visible_user_ids` 四级范围 + `ScopeModelViewSet`），但**覆盖不全、口径不一，存在 8 类漏洞** |
| 是否可直接"维持原样" | **不可以**，必须补齐 |
| 本轮处理 | 保留原有框架不动，只补口径 + 补覆盖 + 修 3 个已存在的功能性缺陷 |

### 1.2 逐条对照 Boss 要求

| 要求 | 改造前 | 改造后 |
|---|---|---|
| 普通员工只看自己的数据 | 部分生效（客户档案因代码缺陷实际全公司可见） | ✅ 全站生效 |
| 员工可访问全部公共功能 | 已满足（学习/通知/会员/招商不受限） | ✅ 保持 |
| 员工看不到其他部门任何人数据 | ❌ 会计凭证/发票/流水/节点、运营计划/内容、外勤进度、审批单、汇报点评、操作日志等 20+ 接口无隔离 | ✅ 已收窄 |
| 部门主管只看本部门全部员工数据 | 部分生效（主管可拉全公司操作日志、全公司线索流转、全公司审批单） | ✅ 已收窄 |
| 主管可访问全部公共功能 | 已满足 | ✅ 保持 |
| 老板/总经理全开、无隔离 | 已满足 | ✅ 保持（`scope_profile='biz'` 仅 BOSS 全量） |

### 1.3 查出的 8 类漏洞（均已修复）

| # | 漏洞 | 影响 | 修法 |
|---|---|---|---|
| 1 | **客户档案数据隔离彻底失效**：`CustomerViewSet` 里 `get_queryset` 被写了**两遍**，后一个覆盖前一个，隔离代码成了死代码 | 任何员工可拉全部 45 个客户 | 合并为单一实现，先走父类范围再筛选 |
| 2 | **HR 被当成"老板"全量放行**：`visible_user_ids` 与 3 处重复定义的 `is_big_boss` 都把 `HR` 算作全量 | HR 可看全公司客户/合同/凭证/业绩 | 拆成两套口径：人事口径保留 HR 全量，**业务口径（`biz_user_ids`）只有 BOSS 全量** |
| 3 | **20+ 个业务 ViewSet 完全没有数据范围**：只做字段筛选，直接 `viewsets.ModelViewSet` | 会计凭证/发票/银行流水/做账节点、广告计划/内容作品/内容数据/渠道预算、外勤进度/线索跟进/任务节点、审批单/审批节点、汇报点评、操作日志 —— 全部跨部门可见 | 统一挂 `BizScopeModelViewSet` + 配置归属字段（含链式与多字段 OR） |
| 4 | **归属字段配错/不存在会直接 500**：如 `MonthlyTask` 配 `owner_field="user"`，但模型没有 `user` 字段 | 非老板账号访问该接口即报 500 | `_scope_paths()` 增加字段路径存在性校验，不存在则自动降级 `created_by`，再不行才不收窄 |
| 5 | **主管/组长建的单据没有归属人**：`perform_create` 只对 EMPLOYEE 自动填 owner | 主管建的数据本部门下属看不到、部门业绩统计不到 | 归属为空时**所有角色**都回填本人 |
| 6 | **部门主管可看全公司操作日志** | 跨部门行为轨迹泄露 | 收敛为「BOSS/HR 全量 → 主管本部门 → 组长本组 → 其他本人」 |
| 7 | **部门/公司业绩接口无鉴权**：`/dashboard/department/<code>/` 可传任意部门 code；`company-performance` 任何账号可拉全公司业绩与全员排行 | 越权查看任意部门业绩、全公司签约额、全员排行 | 部门维度校验（非本部门 403）；公司业绩非老板只回本部门合计与排行 |
| 8 | **增长中心 MANAGER 可看全公司线索** | 与"主管只看本部门"直接冲突 | 新增 `leads_scope_all()`：线索数据仅老板/总经理（或 `GrowthRole.can_view_all` 显式授权）全量，主管回落本部门；**配置类功能（渠道/角色/派单）仍保留 MANAGER 权限，不受影响** |

### 1.4 刻意**不改**的三处（属既定业务规则，非漏洞）

| 位置 | 规则 | 依据 |
|---|---|---|
| 合同数据 | 管理人员（BOSS/HR/MANAGER）及运营部、管理层部门可见全部合同 | Boss 2026-09-13 明确要求 |
| 账套 `BookSet` | 公司共享数据，不按个人归属隔离 | 模型注释中已写明为专项设计 |
| 字典/配置类 | 税种、提成规则、广告平台、渠道、角色、职级、考勤规则、套餐、招商政策、通知公告、汇报模板、学习内容 —— 全员可见 | 这些是"公共功能"的一部分，收窄反而会破坏业务 |

### 1.5 遗留待确认项（1 项）

- 生产上目前 **没有 MANAGER 角色账号**（8 个账号：2 BOSS / 1 LEADER / 5 EMPLOYEE，其中 7 人在运营部），所以本轮针对 MANAGER 的收敛**暂无生产数据可验证**，已在本地 31 人测试库中验证通过。
- 若后续给某人设成「部门主管」，建议先跑一次 `backend/scripts/perm_selftest.py` 复核。

## 二、新增功能改动点

### 功能 1 · 各部门业绩核算与统计，自动向上汇总到老板/总经理

后端原本已有 `department_detail`（单部门业绩）与 `company_performance`（公司业绩），但**没有鉴权**、也**没有汇总入口页**。本轮：

| 文件 | 改动 |
|---|---|
| `apps/dashboard/viewsets.py` | 新增 `can_view_dept()` / `visible_dept_codes()`；`department_detail` 越权返回 403；`department_members` 员工明细仅老板与本部门主管可看；`company_performance` 增加 `scope` 字段（`COMPANY`/`DEPARTMENT`），非老板只回本部门合计与本部门排行 |
| `web/src/views/DeptPerformanceSummaryView.vue` | **新增页面**：4 张指标卡（签约/回款/目标/完成率，合同单数作副行）+ 各部门明细表（含完成率进度条）+ 合计行 + 个人业绩 TOP10；点部门行可下钻 |
| `web/src/router/index.js` | 新增 `/performance/dept`「部门业绩核算」，`leader` 可见（BOSS/MANAGER/LEADER）；原三个隐藏的部门业绩页改为菜单可见的「业绩核算」（电销部/会计部/运营部各自一条） |

**汇总链路**：部门明细 → 部门合计 → 公司合计（仅老板/总经理可见全公司）。主管进来只看本部门，看不到其它部门一行数据。

### 功能 2 · 企业查询跳转国家电子税务局

| 文件 | 改动 |
|---|---|
| `web/src/views/sales/EnterpriseView.vue` | 企业查询搜索框右侧新增「国家电子税务局 ↗」按钮，点击新标签打开 `https://etax.chinatax.gov.cn/` |

> 只加这一个入口，未新增其它网址、未改动查询逻辑。

### 功能 3 · 日报/周报/月报提交后自动汇总流转到部门主管

| 文件 | 改动 |
|---|---|
| `apps/common/permissions.py` | 新增 `department_heads()` / `department_head_ids()` / `report_receivers()`（本部门无主管时自动升级给老板） |
| `apps/reports/viewsets.py` | `ReportOwnerMixin` 新增 `_flow_after_submit()` / `_is_submitted()`；新增 `flow_report_to_manager()`；日报/周报/月报/专项复盘四个 ViewSet 配 `flow_label`/`flow_link`；日报按 `status=SUBMITTED`、周报月报按"填了总结"视为提交，自动落 `submitted_at` |

**流转规则**

1. 接收人 = 提交人所在部门的主管 / 经理（排除本人）
2. 本部门无主管 → 自动升级给老板 / 总经理
3. 每个接收人收到一条站内消息（类型 `REPORT`），点开直达对应汇报列表
4. 全过程写操作日志，可追溯
5. 同一份汇报只流转一次（重复保存不重复推送）
