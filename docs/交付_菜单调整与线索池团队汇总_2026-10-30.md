### 菜单最终顺序（生产实测）

```
入职与成长 → 增长中心 → 运营部 → 电销部 → 会计部 → 外勤部 → 增值业务部 → 行政人事部
→ 工作汇报 → 公司通知 → 会员体系 → 招商合作 → 系统管理
```

- 行政人事部 内顺序：**员工管理、部门与小组** → 组织与人员 → 入转调离 → 考勤与审批 → 薪酬绩效 → 钉钉同步 → 权限管控
- 系统管理 内仅剩：第三方API配置、操作日志、数据储存、云资源对接、个人中心
- 外勤部 → 外勤任务池；增值业务部 → 增值业务部（各自成为独立一级分组，不再折叠在增长中心内）

### 线索编辑 / 删除的规则

- **可改字段**：客户姓名、电话、微信、公司、意向业务、备注（回写 `sales.Lead`）；来源平台、来源账号编号、联系方式类型/内容、客户需求、联系人、获客成本、成交金额、3570 阶段（写 `LeadExt`）
- **不可在本弹窗改**：归属运营 / 承接人 —— 走「分配 / 转派」，避免绕过流转链路
- **校验**：客户姓名不能为空、联系方式不能为空、来源平台必须存在、金额必须为数字
- **留痕**：每次修改写一条操作日志（模块「运营线索池」，动作「修改」，明细列出改了哪些字段）；删除写「删除」日志
- **删除**：软删除（`is_deleted=True`），同时作废对应公海记录并移出公海；历史流转记录保留
- **权限**：老板 / 管理层（可看全量）或该线索的归属运营 / 承接人 / 创建人；其他人 403
- **入口限制**：仅在「运营部 → 线索池」显示编辑 / 删除按钮（增长中心线索工作台保持原样）

### 团队汇总的规则

- **自动触发**：日报提交（status=SUBMITTED）、周报 / 月报保存后自动汇总，无需手工操作
- **周期口径**：日报 `2026-10-30`、周报 `2026-W44`（ISO 周）、月报 `2026-10`
- **范围口径**：提交人所属部门；若提交人挂在小组上，则按「部门 + 小组」单独成表，小组长只看本组
- **正文结构**：标题行（范围 / 周期 / 已提交人数 / 在职人数）+ 逐人分块（今日完成 / 遇到问题 / 明日计划等，按类型自动换字段）+ 数值统计（通话数、加微数、成交数等自动累加）
- **人工编辑保护**：主管编辑保存后标记「已人工编辑」，之后再有员工提交只刷新统计与人数，**不覆盖**已润色正文；点「重新生成」可强制按最新汇报重建并解除标记
- **可见范围**：老板 / 人事看全量；部门主管看本部门；小组长看本组；普通员工看不到（返回 0 条）
- **不支持手工新增 / 删除**：汇总由汇报自动生成（接口对新增 / 删除返回 405）
- **历史回填**：迁移 `reports.0002_teamsummary` 内置回填，把已有已提交汇报按周期补生成汇总（幂等）
